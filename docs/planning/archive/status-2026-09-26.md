## What it is
A local software factory. Humans give requirements and post-deploy feedback. Agents do intake, design, build, verify, package, deploy (plus a deploy_fix repair station), acceptance and deliver. Everything runs in docker compose (dind + factory + web). Apps are deployed to kind running inside dind.

## Decisions
- Hybrid orchestration: a deterministic state machine routes between stations; Claude Agent SDK agents do the work inside them.
- Python engine and FastAPI API. TypeScript UI (React, Vite, TanStack Query). API-first: the OpenAPI contract is used to generate the UI types.
- Reuses BuilderIO practices: per-action policies, hold on missing evidence, skill_prompts overlays, worktree per run, recover rule. Also the shared-actions pattern from agent-native.
- Holdout scenarios are hidden from builder agents; an independent verifier checks them against the live app.
- Model auth: subscription token (CLAUDE_CODE_OAUTH_TOKEN). Human gate: feedback after deploy.
- Workflows are data (ADR-0007 and ADR-0008; "line" was renamed to "workflow"):
  - One active workflow per product line. Immutable versions, with runs pinned to (workflow, version).
  - Seeded from `workflow-templates/`, or imported from GitHub.
  - Role and tool checks block publishing.
- Skills can be imported from GitHub (ADR-0009):
  - Each import is reviewed first (all files, scripts flagged, diff), then installed at the reviewed commit.
  - Private repos use SKILLS_GITHUB_TOKEN.
  - Workflow versions pin the commits they use (`skill_pins`), and runs load exactly those commits.
- The instance-customisable workflow is the product direction: a starter kit customised per client. Auth and roles are deferred.
